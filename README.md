# Eidolon

基于 [Falcor 9.0](https://github.com/NVIDIAGameWorks/Falcor) + [RenderDoc](https://renderdoc.org/)
的**实时渲染研究工程**。目标是把"改一版着色器 → 重建 → 出图 → 抓帧 → 度量 → 出结论"
做成一条可复现、可回溯的流水线，而不是一堆散落的实验脚本。

```
D:\Eidolon
├─ research\       我们的代码：RenderPass 插件库 + 共享 C++ 头
├─ experiments\    一次研究一个目录：图 / 参数 / 记录 / 产出
├─ analysis\       度量脚本（PSNR/SSIM/FLIP、基线对比、汇总）
├─ tools\          构建 / 运行 / 抓帧 / 脚手架（PowerShell）
├─ docs\           环境、架构、工作流、抓帧、实验规范、排错 + ADR
├─ vendor\falcor\  Falcor 9.0，只读子模块
├─ assets\         大场景与环境图（gitignored）
└─ out\            帧、日志、.rdc（gitignored）
```


## 它是怎么接上 Falcor 的（一句话版）

Falcor 必须是顶层 CMake 工程，而它只通过
`Source/RenderPasses/CMakeLists.txt` 里的 `add_subdirectory()` 发现插件库。
所以 `tools\sync-passes.ps1` 从 `git show HEAD:` 取纯净上游内容，把我们的
`research/passes/*` 作为**绝对路径子目录**注入到一个带标记的生成块里：

```cmake
# >>> eidolon overlay (generated by tools/sync-passes.ps1; do not edit)
add_subdirectory(D:/Eidolon/research/shared     ${CMAKE_BINARY_DIR}/eidolon/shared)
add_subdirectory(D:/Eidolon/research/passes/HelloPass ${CMAKE_BINARY_DIR}/eidolon/HelloPass)
# <<< eidolon overlay
```

上游源码一行不改；撤销 = `tools\clean-passes.ps1`。完整推理见
[`docs/01-architecture.md`](docs/01-architecture.md) 与
[ADR 0002](docs/adr/0002-overlay-injection.md)。

## 约定速查

| 事项 | 约定 |
|---|---|
| 插件库名 | PascalCase；= 目录名 = CMake target = DLL 名 = C++ 类名 |
| pass 类型名 | 与类名一致，图脚本里 `createPass("HelloPass")` 用它 |
| 端口名 | 小写驼峰（`color` / `depth` / `motion`） |
| 实验目录 | `NNNN-kebab-slug`，编号自动递增 |
| 产物 | `out\`、`experiments\*\results\`、`assets\` 全部不入库；`.rdc` 永不入库 |
| 构建配置 | 默认 `RelWithDebInfo`；Debug 只用于调试层排查，不做性能结论 |

## 三个待铺的研究方向

结构已经为此留好扩展位（帧资源契约见 `docs/01-architecture.md` 第 5 节）：

1. **实时 GI / 路径追踪 + 时域降噪** — 以上游 `MinimalPathTracer` 为模板写 RT pass，
   接 `TAA` / `NRDPass`；
2. **超分与时域重建** — 新增 upscaler pass，消费 `color` / `depth` / `motion` 三件套；
3. **材质 / 体积 / SDF** — pass 只读 scene，靠 `setScene()` 接管几何，输出同一套契约。

每个方向落地时，先建实验目录写清问题与假设，再动代码。
